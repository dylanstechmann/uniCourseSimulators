# Autograder design

## Current boundary

The static reader exposes public formative answers and has no server grade record for those items. The backend covers choice, numeric, bounded symbolic, narrow data interpretation, fielded structured-rubric, fixed-axis graph-coordinate and constrained CSV numeric-table formative items. It also supports a protected assignment submission flow that reuses these deterministic graders against enrollment-pinned content. Structured criteria map to keyed selections, graph criteria map to separate authored x/y coordinates, and CSV criteria map to parsed numeric cells; none infer concepts from prose. The data composite separately grades a unit-aware calculation and an evidence-bounded choice. The assignment flow is tested on synthetic fixtures and does not mean any shipped package has summative work.

Protected graded question packages may be referenced by `private://<relative-path>` and are loaded only below the separately configured `PRIVATE_ASSESSMENTS_ROOT/courses/<course-id>/` directory. Compose mounts `COURSELAB_PRIVATE_ASSESSMENTS_PATH` read-only for API-side use; public course files and learner DTOs do not carry answer keys. The public and private roots must not overlap. Traversal, missing files and symlink escapes fail closed, and the existing enrollment snapshot pins the exact file checksum. Current course packages do not use this source yet; no production answer key is committed.

## Grade authority

Implemented immutable attempts record learner, course/question IDs, course version, grader-policy version, response, score, diagnosis, time and a SHA-256 digest of the resolved authored question specification plus grader-policy version and selected variant ID. Alembic migration 0002 leaves historical attempts unpinned (`question_spec_sha256=null`) while new attempts record a digest. The digest is server-side only and omitted from learner attempt DTOs because hashes of answer-bearing specifications could be guessed offline. A digest can verify equality, but the current appeal path does not compare it. It cannot reconstruct a retired specification without an immutable package archive. Authored formative variants use a server-signed, seven-day token containing a random seed; a keyed HMAC selects the same authored form on replay. Tokens bind course, package version and question ID. Current implementation selects among finite, explicitly written forms; it does not generate numeric parameter variants. Deterministic grading or explicit analytic rubrics determine scores. A correct value/selection cannot alone establish sound reasoning. Self-assessment and provisional design feedback are separate from grades.

Enrollment now snapshots assessment categories and manifest-defined assignment instances by course version. The snapshot records category weights, aggregation mode, assessment types/roles, points, objective/question references, release/deadline, attempt limit, highest/latest scoring rule, source path for internal use, and the source-file SHA-256. The authenticated assessment-plan response strips source paths, objective/question IDs, digests, and key material. Same-version edits do not mutate an existing plan snapshot; an explicit enrollment update creates a new snapshot and preserves the old metadata.

The weighted grade calculator is a deterministic pure function using `Decimal`. Within a category it supports point-weighted or equal-assessment-percentage aggregation; per assignment it selects either the highest or latest valid attempt within the configured limit. Unreleased items are excluded. Missing work counts as zero only after its deadline; the deadline instant itself remains open. Current-to-date percentages normalize weights over categories with released evidence or overdue work; the original configured weights remain intact. Alembic revision 0006 adds append-only, enrollment/version-bound submissions. The API serves whitelisted question DTOs from SHA-256-verified authoring files, enforces release, strict deadline and attempt limits, persists answers/results/criterion feedback, and connects selected attempts to the gradebook calculator. Revision 0007 adds a separate appeal and append-only instructor decision per graded submission. The authorized review queue reconstructs answer-free questions only when the saved course version, source hash, and aggregate grader digest still match; otherwise only a decline can be recorded. Score adjustments remain separate from automatic results and feed the weighted calculator under its existing highest/latest policy. The frontend shows saved feedback, appeal status, and original/effective scores. Late penalties and historical-content recovery remain unimplemented. All 25 live packages remain formative-only, so this path currently shows no course grade for catalog courses.

Layer feedback as diagnosis, targeted hint, misconception, next step, policy-controlled solution, exact lesson/source links. Planned diagnoses distinguish arithmetic, units/dimensions, misapplied equations, unsupported biology, correlation/causation, missing controls, overgeneralization, weak reasoning and promising incomplete approaches. Reasoning claims need response evidence.

## Planned plugins

| Plugin | Required behavior |
| --- | --- |
| Choice/multiple select | Explicit shape and partial-credit policy |
| Numeric | Unit conversion/dimensions, tolerance, significant figures, independent recalculation |
| Symbolic | Bounded rational-expression equivalence using SymPy; implemented for formative practice |
| Structured concepts | Explicit criterion-to-field analytic rubric; keyed categorical responses implemented for formative practice; no natural-language or keyword scoring |
| Data interpretation | One composite numeric-plus-choice item with transparent per-field partial credit; a fixed-axis graph plugin grades entered coordinates, while general graph/table response tools and interpretation grading remain planned |
| CSV upload | A bounded UTF-8 numeric-table profile is implemented: exact ordered header, unique known row keys, limited bytes/columns/rows/cell lengths, and rubric-scored numeric cells. No upload is executed. General CSV analysis and other file types remain planned. |
| Code | Separate isolated worker using pytest; never API execution |
| Design | Transparent provisional rubric, manual review/appeal (basic audited appeal workflow implemented; design-response rubric remains future work) |

Future generated parameter variants must recompute reproducible specifications and pass independent recalculation tests. Current authored alternatives must have unique IDs, validate as complete standalone questions after overrides, and have distinct non-placeholder prompts. Human appeal decisions append actor/reason/time records and retain original attempts. Weights and release policies are explicit. Legacy packages offer practice evidence only, not semester grades.

## Feedback providers: planned

Deterministic no-LLM mode is default. Optional OpenAI-compatible, Anthropic, OpenRouter-compatible and Ollama providers may elaborate feedback without score changes. Require criteria, response evidence, missing/incorrect concepts, confidence, provisional AI label and manual-review request. Keys never reach browsers/logs. No provider production readiness is asserted without tests.

Adversarial tests cover alternate forms, wrong units, near misses, invalid concepts, malformed inputs, injection/solution requests, keyword repetition and malicious/infinite code. Mutation tests must fail broken rules. Code safety checks require the actual runner, not a mock claiming isolation.

## Enabled implementation

Learners may request one human review per immutable attempt. Alembic revision 0003 stores the appeal and the single decision separately; revision 0004 adds a persisted instructor role that can be granted or revoked only through the operator CLI after out-of-band identity review. Registration and HTTP endpoints cannot set the role. The automatic score/result is never overwritten. A score adjustment is labeled in attempt history and reflected in the formative gradebook. The instructor view resolves the saved variant and compares its question-specification digest. Missing, changed, unpinned or mismatched specifications block score adjustment and upholding; a reviewer may decline with an explanation. Historical content archives are not yet available, so currently only the exact installed course version can be reviewed. This is an audited practice-score exception path, not full rubric-based instructor grading, protected exams or institutional review.

The global grader policy identifier is `practice-v10`, which adds fixed-axis graph-coordinate scoring; historical attempts keep their recorded versions.

The deterministic grader supports single-choice, multiple-select, bounded symbolic rational expressions, Decimal-based finite numeric checks with authored tolerance, the narrow data-interpretation composite described below, and structured rubric items with criterion-to-field mappings. Multiple-select answers define either all-or-nothing or the clamped equal-share rule: score = points × max(0, correct selected − incorrect selected) / number of keyed correct choices. Learners see the policy before submitting. Empty, repeated, non-integer, out-of-range and unsupported-policy responses fail closed. This rule is transparent but is not a validated universal grading policy.

Fixed-axis graph items expose axis labels and bounds, point labels, and source replicate observations. The learner enters x/y coordinates and sees an accessible SVG preview and the underlying data table. The public lesson response omits expected y coordinates, tolerances and rubric evidence. Each coordinate is scored independently through the bounded numeric grader, so missing and inaccurate coordinates receive no credit while correct coordinates retain partial credit. The content validator recalculates each authored y mean from its source replicates and checks the x mapping. This plugin does not evaluate axis selection, graph type, error bars, interpolation, model fit, visual hand-drawing, or scientific interpretation; numeric coordinate entries are not a substitute for those skills.

Symbolic answers use a deliberately restricted expression language parsed from an AST. It accepts declared variable names, finite base-10 integer/decimal literals, parentheses, unary signs, addition, subtraction, multiplication, division, and integer powers from −8 through 8 (`^` or `**`). Decimal literals become exact rationals. Calls, attributes, subscripts, imports, assignments, comparisons, undeclared names, and other Python syntax are rejected; the service never calls `eval`, `sympify` or `parse_expr` on learner text. Bounds include 256 characters, 64 AST nodes, depth 14, eight declared variables, 128 estimated numerator/denominator terms, degree 64, 512 SymPy operations and limited numeric literal size. Authored assumptions are restricted to typed boolean flags for `real`, `positive`, `nonnegative`, `nonzero` and `integer`. SymPy `cancel` compares rational functions; this intentionally treats expressions as equivalent over their common domain and does not prove that a learner stated domain restrictions. Trigonometric, logarithmic, radical, matrix and general symbolic-calculus expressions are unsupported. Correct symbolic results receive full credit with reasoning explicitly unassessed; incorrect but valid expressions receive no partial credit.

Data-interpretation questions can combine a numeric field and a single-choice evidence claim. Each field has an explicit answer specification and positive points; field points must sum to the parent item total. Learners may submit a subset of fields and receive independent partial credit. Numeric fields use the existing unit, dimensional, tolerance and precision checks. Choice fields compare exact option indexes. Unknown fields reject the whole response. The public question DTO includes only field IDs, prompts, options, units and points; `field_specs` and answer indexes remain server-side. Feedback reports each field's score and diagnosis. This narrow plugin does not grade prose, plots, arbitrary tables, causal explanations, or keyword overlap. A correct result still leaves reasoning unassessed.

Structured items use two to twenty explicit rubric criteria, each mapped by durable ID to one visible single-choice response field. Rubric points must match the field points and sum to the question total; response and solution IDs must match exactly. The grader uses the ordinary choice grader for each field and returns criterion-labeled scores, missing-field feedback and deterministic partial credit. Unknown fields earn zero for the entire item. Authored evidence descriptions support instructors and validators but stay out of public DTOs. This supports structured rubric checks for selected experimental controls, mechanisms and evidence limits; it does not grade a typed explanation, identify reasoning from keywords, or demonstrate the learner's underlying justification. The current original cell-biology example remains formative practice in a partial package.

CSV uploads are currently limited to a 32 KiB UTF-8 CSV profile with at most 20 ordered columns, 50 expected rows, and 1000 characters per cell. A submission is base64-encoded in the attempt request, decoded in the API process, parsed with Python's standard CSV reader, and never written as an executable or passed to a shell. The exact header must match the manifest; duplicate and unknown row keys, malformed quoting, extra cells, invalid UTF-8, invalid base64, and oversized inputs receive no credit. Missing expected rows/cells can receive partial credit; valid cells are graded through the ordinary bounded numerical/unit grader against explicit criteria. Authored checks include independent source values and a count/mean operation so the content validator recalculates each answer within its tolerance. The public DTO exposes only `text/csv` and the size limit, not source values, expected outputs, rubric evidence, or calculation rules. The sample cell-biology item scores replicate counts and group means only; it does not analyze uncertainty, infer causality, run learner code, or support arbitrary CSV tasks.

For numeric items, deterministic conversion uses an intentionally constrained parser and explicit unit table. It supports common SI and biology units, liter and molar concentration units, selected derived SI units, products, quotients, parentheses, and bounded integer powers. For example, `μmol/min`, `mmol/(L·h)`, `m/s²`, `N`, and `kJ/mol` are parsed into SI scale and seven base dimensions. Micro-symbol variants normalize; SI symbol/prefix case remains significant (`mV` differs from `MV`, `ms` from `mS`). An answer is converted into the authored unit before applying that unit's absolute tolerance. Optional dimension exponents can be authored using the seven documented bases and are checked against the unit expression. A conflicting inline and unit-field answer is rejected unless the expressions are equivalent. When unit entry is optional and absent, the learner's number is interpreted in the authored unit, retaining the prototype's explicitly disclosed legacy policy.

This is not a general-purpose unit library. Contextual labels (`pH`, assay `units`, and `mol ATP`) are retained as exact-label-only quantities: they cannot be combined with other units or converted to another label. Unknown symbols and affine temperature units fail closed; an unsupported authored unit disables grading with an explicit error, and an unsupported learner unit gets no credit. The question schema bounds authored dimensions. Relative tolerance combines with absolute tolerance by `allowed_error = absolute_tolerance + relative_tolerance × |authored_answer|` after converting into the authored unit; relative tolerance is bounded from 0 through 1 and remains well-defined for a zero answer. Optional significant-figure requirements are bounded to 1–12 and are checked only after the numeric value is within tolerance. The count follows lexical decimal notation: leading zeros do not count, trailing decimal zeros do, exponent digits do not, and trailing zeros in an integer without a decimal point are ambiguous and therefore do not count (`80` = 1; `80.` = 2; `8.0e1` = 2). The UI states the requirement and explains how to express precision. Grader v5 pins this policy; historical attempts retain their recorded grader version.

The API records immutable attempts; tests verify owner isolation, malformed/injection input, near misses, alternate exponent forms, wrong units, no score mutation and no code-execution route. Learner gradebooks aggregate best formative checks and objective evidence for the current enrolled course version. Repeated attempts increase the attempt count but not distinct-item coverage; objective points use the best score once per tagged question. A provisional practice-mastery indicator requires at least three distinct tagged items, at least 80% of the objective's tagged items attempted, and at least 80% of possible points on attempted items. The API returns these thresholds and the policy version so the learner can interpret the result. This is explicitly a study signal: short formative checks do not establish reasoning, transfer, course mastery, credit, or course completion. Objectives with fewer than three authored questions cannot reach the provisional state. Previous-version attempts remain in history but do not enter the new version's aggregate. Feedback remains deterministic and unreleased solutions/specifications remain withheld. The disabled runner/provider interfaces are extension points, not implemented isolated execution or LLM integrations.
