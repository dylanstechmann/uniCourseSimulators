# Content contract version 1.0

These JSON Schemas use Draft 2020-12 and are application-independent authoring contracts. A valid manifest describes what exists. It does not establish course completeness, institutional equivalency, or review approval.

`course.schema.json` requires maturity, durable identities, prerequisites, Bloom-style outcomes, workload, schedule, modules, assessment references, grading policy, sources, accessibility, history, review, and explicit limitations. `question.schema.json` discriminates choice, multiple-select, numerical, symbolic, structured, graph/table/data interpretation, Python, upload, and design specifications. The enabled deterministic surface includes structured items whose visible criteria each map to a keyed single-choice field; this does not grade natural-language prose. A fixed-axis graph profile exposes source observations and grades learner-entered x/y coordinates separately, while expected coordinates and rubric evidence remain server-side. Its validator independently recalculates the plotted means. It does not assess graph type, axis selection, error bars or scientific interpretation. One constrained CSV upload profile parses size-limited UTF-8 numeric tables as inert data, checks an exact authored header and unique row keys, and scores output cells against explicit numeric criteria. General graphing, data files, arbitrary analyses, design grading, and code execution remain unsupported. `question-bank.schema.json` groups public practice items. `source.schema.json` validates the source registry and conservative project-use permissions.

Assessment manifests may define optional assignment titles, weeks, category IDs, ISO release/deadline timestamps, attempt limits, and `highest`/`latest` attempt scoring. A graded policy requires unique categories with decimal weights summing exactly to one, every graded assignment mapped to one category, and every category used. Formative-only policies cannot contain graded work or course-grade categories. `category_aggregation` is `points` (point-weighted within a category) or `assessment-average` (each assignment percentage counts equally). The current weighted-grade calculator treats work due exactly at the calculation time as still open, later missing work as zero, excludes unreleased work, and normalizes only active category weights for a current-to-date percentage. This is a tested calculation core, not yet connected to graded submission records; no present course awards a course grade.

`curriculum-map.schema.json` describes catalog-only planning nodes, prerequisite relations, pathway sequences, and source-linked curriculum alignments. It is validated together with the course manifests so IDs and prerequisite edges resolve across both kinds of node and the combined graph is acyclic. Catalog nodes remain metadata; they do not satisfy course-package completeness gates or become enrollable teaching material.

All content paths are relative to their course directory. The validator rejects absolute paths, parent-directory escape, external symlinks, missing files, unresolved references, prerequisite cycles, empty and duplicate material, placeholders, and incomplete answer specifications. Source IDs refer to `content/sources/registry.json`. Objective IDs must be durable and unique within the course.

At enrollment, the API stores an immutable versioned assessment-plan snapshot, including policy/category definitions, assignment schedule and attempt rules, and a SHA-256 digest of each referenced source file. The learner plan endpoint omits paths, question IDs, answer specifications, and source digests. Updating enrollment adds a snapshot for the new version and retains prior snapshots. This metadata history does not archive all course files or support historical regrading.

Migrated seeds retain all legacy IDs, questions, retrieval cards, and case criteria. Their compact readings are accepted only while they are `partial`, have verified `legacy-prototype` provenance, and match the expected legacy reading paths. They produce explicit depth warnings. Newly authored short content receives no migration exception.

The six maturity labels are `catalog-only`, `outlined`, `partial`, `beta`, `complete`, and `externally reviewed`. Catalog records can have empty instructional inventories, but limitations must explain them. `complete` and `externally reviewed` require the validator's full-course gate, independently recorded validation evidence, and real review records for the specified version. A reviewer record must refer to a readable evidence document; inventing one is prohibited. Automated metadata checks cannot establish a reviewer's actual qualification or authenticity.

All migrated keys are marked `public-practice-authoring`: they were already publicly delivered by the prototype and remain intentionally inspectable formative material. Restricted production exam keys must be provisioned outside publicly distributed content and frontend bundles. Do not commit secret keys, learner submissions, or production answer specifications.

Run `python tools/validate_content.py` from the repository root. `--json` provides machine-readable errors, warnings, and inventory counts. `--check-links` additionally checks registered HTTPS references with a bounded timeout. Link checks require network availability; their results must be recorded before claiming a full quality gate passed.
